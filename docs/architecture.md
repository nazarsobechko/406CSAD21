# Архітектура Build Engineer

## Проблеми, які вирішує агент

Агент зменшує кількість ручних кроків під час створення JavaScript-проєкту,
уніфікує npm-збірку та Jest-тести і забезпечує однакову CI-перевірку на
Linux, Windows і macOS. Він також визначає межі безпечних змін: не видаляє
файли, не переписує Git-історію, не публікує секрети і не змінює захист
гілок.

## Skills

- `project-scaffold` готує мінімальні `src/`, `tests/`, README і `.gitignore`.
- `build-and-test` додає `package.json`, scripts `build`, `start`, `test`,
  функцію `add` і Jest-тест `BasicAddition`.
- `github-actions` створює `ci.yml` з одним job і matrix трьох ОС та `ci.sh`,
  який є єдиною точкою запуску збірки й тестів у CI.

Skills розділені за відповідальністю, тому повторний запуск одного етапу не
повинен дублювати налаштування іншого.

## Commands

`git-init` перевіряє або безпечно готує Git; `create-project`,
`create-build` і `create-actions` послідовно готують проєкт; `check` лише
перевіряє; `init` оркеструє всі етапи.

## Дані між етапами

Кожен етап отримує кореневий каталог, поточний Git-статус, доступні файли та
результати попереднього етапу. Передаються шляхи створених файлів, коди
завершення, діагностика і факт успішності перевірок. Вміст секретів між
етапами не передається.

## Обробка помилок оркестратором

`init` запускає етапи строго послідовно. Ненульовий код або невдала
перевірка негайно зупиняє оркестрацію. Повертаються назва етапу, команда,
код і первинне повідомлення; наступні етапи не виконуються. Повторний запуск
дозволений, бо кожен етап спочатку читає наявні файли та не руйнує сумісну
конфігурацію.
